## BUG 清单（本轮）

### 真实 BUG（已修）

| ID | 级别 | 模块 | 根因 | 修复 |
|----|------|------|------|------|
| **BUG-B** | P0 🔴 | BFF `sites/[siteId]/route.ts:78` + `pages/[pageId]/route.ts:84` | `NextResponse.json(null, {status:204})` 违反 Fetch 规范（204 不允许 body，但 `.json(null)` 会序列化成字符串 `"null"` 并设 content-type）→ `TypeError: Invalid response status code 204` → Next.js 兜底 500 | 改为 `new NextResponse(null, {status:204})`——与其它 7 个工作正常的删除端点一致 |
| **BUG-E** | P0 🔴 | `FormSaveRequest.java` | `pageId` 字段无 `@NotBlank`，但 `forms.page_id NOT NULL`（DB 约束）→ 缺 pageId 时穿透到 DB 抛 `SQLIntegrityConstraintViolationException` → 500 INTERNAL | DTO `pageId` 加 `@NotBlank`，缺值时返回 400 INVALID_ARGUMENT |
| **BUG-F** | P1 🟡 | `AuthFilter.NO_AUTH_PATHS` | `PingController` 提供 `/backend/healthz` 健康端点，但 AuthFilter 白名单只列了 `/backend/ping`，导致 `/backend/healthz` 缺 X-User-ID 时返回 401 | 白名单加 `/backend/healthz` |

### 假阳性（学习沉淀，避免重蹈）

| 现象 | 误判 | 真相 |
|---|---|---|
| **BUG-A** 公开端点 `/backend/api/public/...` 返回 401 | 误以为是 AuthFilter 配置错误 | **测试方法错误**：路径多塞了 `/api`。后端 controller 路由 `/public/*` + context-path `/backend` + AuthFilter 白名单 `/backend/public/` **三者完全自洽**，由 `PublicPageContractTest` 契约测试验证。**正确公开 URL 是 `/backend/public/sites/{slug}/pages`** |
| 公开 submit 报 "contact: must not be null" | 误以为是 BUG | **请求体格式错误**：`contact` 必须是 `Map<String,String>`（如 `{"phone":"..."}`），不是直接传 `phone` 字段 |

### 设计澄清（非 BUG）

| 现象 | 设计意图 |
|---|---|
| `BFF users/[id]` 无 DELETE 路由（HTTP 405）| 用户只能 disable 不能物理删除，避免数据完整性问题 |
| `BFF leads/[id]` 无 DELETE 路由（HTTP 405）| 线索只能状态流转，不能物理删除（合规要求） |
