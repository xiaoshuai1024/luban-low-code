## 修复成果

### ai.spec @smoke 修复（4+4 处 spec 错误，非业务代码）

**原假设**：FeatureGate `ai.assistant` 未开 → 按钮不可见
**真实根因**（调研颠覆原假设）：
1. 后端 `FeatureGateService.KNOWN_KEYS` **完全没有 ai.* key**（只 6 个商业化 key：lead_capture / realtime_collab / page_versioning / poster_export / analytics / ab_testing）
2. 前端 `useFeatureGate` DEFAULTS 全 `true`，`AiAssistantPanel` 只用 `ai.design_to_page` 不读 `ai.assistant`
3. `PageEditor.vue` 的 AI 按钮**无 v-if**（永远渲染），文案是「✨ AI」不是「AI 助手」
4. 编辑器加载 marker 是 `textbox placeholder="页面名称"`，不是 text 节点

**修复**：
- `getByRole('button', { name: /AI 助手/ })` → `/✨\s*AI/`（4 处）
- `getByText('页面名称')` → `getByPlaceholder('页面名称')`（4 处）

### SiteDeletedEvent 孤儿事件（保留 + 文档化）

**事实**：全仓 grep 确认零消费者。`SiteCascadeDeleter.deleteChildren` 在主事务内同步完成 7 表级联删除，事件本身不触发任何副作用。

**决策**：按 `luban-engineering-principles` 保留作为未来扩展点（不删），加 Javadoc 注释明确：
- 当前状态：孤儿事件，无副作用
- 设计意图：未来 Analytics 事件归档/Campaign 软删的扩展点
- 不要删除：会破坏扩展性 + SiteAggregateTest 已断言事件发出

### leads.spec @core（无需 seed，DB 已有数据）

DB 中已有 3 条线索（含 2 条挂在 TEST_SITE_ID 下），spec 的 protective skip 自动放行，全部 @smoke + @core（除 test.fixme 的 404 用例）通过。
