## BUG 清单（本轮）

### 真实 BUG（已修）

| ID | 级别 | 模块 | 根因 | 修复 |
|----|------|------|------|------|
| **BUG-H** | P0 🔴 | `TemplateInstalledEvent` / `TemplateAggregate.install` / `TemplateInstallHandler` | DDD 重构遗漏：聚合根 `install(... int version)` 收 version 参数但创建 Event 时**不传 version**；Event record 也无 version 字段；handler 写 `template_installations` audit 表时 version 为 null → DB NOT NULL 约束违反 → REQUIRES_NEW 事务回滚 → **page 创建被静默吞掉**（主事务已提交）。API 返回 200 但 page 永不创建 | ① Event record 加 `int version` 字段 ② aggregate 创建 event 时传 version ③ handler 用 `event.version()` 写 entity ④ 单测加 version 透传断言 |
| **BUG-G** | P1 🟠 | BFF `templates/[id]/publish/route.ts` 缺失 | 后端 `POST /templates/{id}/publish` 存在，但 BFF 没有对应代理路由 → 前端调 BFF 返回 Next.js 404 fallback 页 | 新建 `publish/route.ts`（与 install/route.ts 同模式，纯代理） |
| **vite watch 死循环** | P1 🟡 | `vite.config.ts` | vite 默认 watch 整个仓，E2E 跑生成 `test-results/` / `playwright-report/` → reload → 触发更多 reload → 占满 CPU | `server.watch.ignored` 排除测试产物 |
| **vite host IPv6-only** | P1 🟡 | `vite.config.ts` | vite 6 默认仅绑 `::1`，Playwright baseURL 用 `127.0.0.1` → `ERR_CONNECTION_REFUSED` | `server.host: '127.0.0.1'` 显式绑 IPv4 |

### 反模式沉淀

新建规则文件 `.agents/rules/luban-e2e-anti-patterns.md`，记录 6 类反模式：
1. Playwright hover-show 按钮：必须先 hover 触发显示
2. vite watch 死循环：测试产物触发 reload
3. vite host 默认绑 IPv6：Playwright 用 IPv4 拒绝
4. DDD 事件字段遗漏：聚合根方法签名收参但不用（**BUG-H 的元模式**）
5. BFF 路由缺失：后端有但 BFF 没代理
6. E2E 端口默认值：必须对齐 Makefile dev-* target

每条含反模式描述、根因、修复代码片段、检查 checklist。已加入 AGENTS.md 规则索引。

## 关键洞察：BUG-H 的元模式价值

BUG-H 是 DDD 重构典型反模式——**事件解耦时漏字段**：
- 旧代码（直接调用）：`pageService.create(siteId, path, schema)` —— 参数列表清晰
- 新代码（事件解耦）：`agg.install(schema, siteId, name, path, version)` —— 收 version 但**没用**
- Event record 漏字段 → handler 取不到 → DB 违反 → 整事务回滚
- **单测存在但断言不全**（只断言 id/siteId/pageId，漏 version）→ 测试通过但生产阻断

这类 BUG 极易在 DDD 重构中引入，已沉淀为 §4 checklist：
- [ ] Event record 字段 = 聚合根方法的所有参数 + occurredAt
- [ ] 聚合根创建 Event 时**逐参数对照**
- [ ] Handler 消费时**逐字段写入**
- [ ] 单测断言**全部字段透传**
